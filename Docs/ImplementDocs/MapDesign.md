## 문서명: `261110 Feature MapDesign`

## 1. 구현 일자
- 일자: 2026-11-10 (화요일)

## 2. Core Contents
- 구현 방향: 지형 TSV 시트 → JSON (지형 정의) + 지형 SO (Cube 프리팹) → 스테이지별 맵 TSV (칸별 Terrain ID) → 10×10 그리드 생성
- 목표: 지형 규칙, 지형 외형, 맵 배치를 나누어, 스테이지 교체 시 맵 시트만 바꾸면 되도록 한다.

## 3. F-03 맵 외부 데이터 (설계)
- What : 데이터 구성
  | 데이터 | 형식 | 내용 | 스테이지별 여부 |
  |---|---|---|---|
  | 지형 정의 (TerrainData) | TSV → JSON | ID, TileName, RequireMove, IsMoveAvailable | 공통 |
  | 지형 외형 | SO | ID별 Cube 프리팹 (시트에서 받지 않음) | 공통 |
  | 맵 디자인 | 스테이지별 TSV | 셀마다 Terrain ID, 시트 격자 = 맵 격자 | 스테이지별 |
  | 스폰 위치 | 맵 시트와 별도 TSV | 유닛 배치 좌표 | 스테이지별 |
- What : 좌표 규칙 - 맵 시트의 A1 셀을 원점 (0, 0)으로 둔다.
- What : 이동 판정 - `IsMoveAvailable`로 진입 가능 여부를 먼저 검사하고, 가능할 때만 `RequireMove`만큼 이동력을 소모한다. 진입 불가 지형의 `RequireMove` 값은 사용하지 않는다.
- What : 예외 처리
  - SO에 외형이 없는 Terrain ID: 에러 로그 출력, 기본 큐브로 대체
  - 지형 정의에 없는 Terrain ID: 에러 로그 출력, 기본 큐브로 대체, 진입 불가 칸으로 처리
- Where: 지형 TSV 시트, 스테이지별 맵 TSV 시트 (스크립트 경로는 구현 후 기록)
- Tune : 지형별 이동 비용·진입 가능 여부 (지형 TSV 시트), 지형 외형 (지형 SO), 칸 배치 (맵 TSV 시트)

## 4. 선택 이유
- 지형 정의와 외형 분리: 스프레드시트는 Unity 에셋(프리팹)을 참조할 수 없으므로, 수치는 시트에서 받고 외형만 SO에 둔다. SO에는 이동 관련 수치를 두지 않아 값의 출처를 하나로 유지한다.
- 맵에 ID 기입: 지형 이름이 바뀌어도 맵 시트를 고칠 필요가 없다.
- 시트 격자 = 맵 격자: 시트에서 맵 모양을 눈으로 보며 디자인할 수 있다.
- 스테이지별 시트, 스폰 분리: 스테이지 교체 시 해당 스테이지 시트만 바꾸면 되고, 지형 정의는 모든 스테이지가 함께 쓴다.
- 선검증 후 비용: 진입 가능 여부와 비용을 나누어, 이동 판정 흐름을 단순하고 직관적으로 유지한다.
- 미정의 ID는 진입 불가: 잘못된 데이터로 원래 막혀야 할 길이 뚫리는 것을 막는다.
